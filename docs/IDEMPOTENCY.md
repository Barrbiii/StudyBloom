# Повтор создания после потери ответа

POST задач, событий, предметов, дедлайнов, занятий, привычек, шаблонов повторений
и шагов поддерживают Idempotency-Key (16–128 ASCII букв/цифр/_/-). Заголовок
необязателен для совместимости со старыми клиентами. Ключ относится к пользователю,
маршруту и нормализованному телу: одинаковый запрос возвращает ту же запись201,
другое содержимое с тем же ключом —409. Создание и квитанция коммитятся атомарно.
Уникальный индекс защищает одновременные запросы PostgreSQL; повтор получает запись победителя.

Квитанции не содержат тело ответа, пароль или токен. После удаления записи квитанция
становится отметкой удаления: повтор возвращает410 и не создаёт удалённое заново.
Текущее состояние существующей записи может отличаться от первоначального после правок.
Квитанции не входят в личный JSON, но сохраняются в полном backup PostgreSQL.

Клиент хранит случайный ключ только в памяти открытой формы. Потеря ответа сохраняет
ключ для повтора тех же данных; правка данных или подтверждённый успех начинают новое
намерение. После закрытия/перезагрузки формы ключ не восстанавливается: сначала проверь
список, прежде чем вручную создавать то же заново. Автоматических повторов POST нет.
PUT и отметки дней работают по своим существующим идентификаторам; login/password,
Pomodoro start и генерация периода не оборачиваются этим механизмом (у последних уже
есть ограничение активной сессии/уникальность дат). Это не аутентификационный токен.

API-тесты покрывают8 типов, конфликт, удаление, ошибку валидации и другого пользователя.
Браузер намеренно теряет ответ после реального201 сервера и проверяет единственную запись.
PostgreSQL выполняет два создания одновременно и сравнивает id результата.
