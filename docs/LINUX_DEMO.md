# Демонстрация StudyBloom на Linux

Выбор Linux-компьютера или виртуальной машины пока отложен пользователем.
Текущий macOS Docker не заменяет финальную проверку развёртывания на Linux.
GitHub Actions проверяет Ubuntu; результат сборки сам по себе не является хостингом.

## Подготовка

На выбранной Linux-машине нужны Git, Docker Engine и Docker Compose plugin.
Установка зависит от дистрибутива; используйте инструкции Docker для него.
Проверка доступности: `docker --version` и `docker compose version`.
Для доступа преподавателя машина должна находиться в одной сети с его устройством.

## Запуск

```bash
git clone https://github.com/Barrbiii/StudyBloom.git
cd StudyBloom
docker compose up --build -d
docker compose ps
curl --fail http://localhost:8000/api/health
```

Интерфейс: http://localhost:5173. API: http://localhost:8000/docs.
На устройстве преподавателя: `http://IP_LINUX_МАШИНЫ:5173`.
Адрес машины можно узнать командой `hostname -I`; выберите адрес в сети точки доступа.
Если доступ закрыт, разрешите входящий TCP 5173 только для локальной сети штатным
брандмауэром дистрибутива. База данных наружу не опубликована.

Пока аккаунты не реализованы, все записи общие. Для демонстрации используйте
только синтетические данные в отдельной базе. Публичное размещение пока не готово.

## Проверка перед защитой

1. Открыть интерфейс со второго устройства в той же сети.
2. Создать предмет и дедлайн, проверить календарь месяца и недели.
3. Изменить дату дедлайна, обновить страницу: изменение должно сохраниться.
4. Перезапустить сервис через `docker compose restart` и проверить сохранность.
5. Проверить свежие тесты и сборки в GitHub Actions.

Остановка с сохранением базы: `docker compose down`.
Не используйте `docker compose down -v`: этот флаг удаляет том PostgreSQL.

Если сервис не отвечает, проверить `docker compose ps` и
`docker compose logs --tail=100 backend frontend db`. Не публикуйте логи с секретами.
Полноценный сценарий защиты будет дополнен после аккаунтов, расписания и таймера.

## Обновление установленной версии

Из папки проекта выполните `bash scripts/update.sh` на Linux или macOS.
Скрипт сначала проверяет чистоту рабочей копии, ветку main и доступность Docker.
Он отказывается переписывать расходящуюся историю и не удаляет тома базы данных.
После обновления исходников пересобирает и запускает сервисы. Работающий Docker
необходим для этой команды. Первая установка по-прежнему описана выше.
Ошибка сборки не означает автоматический откат исходников; предыдущие контейнеры
обычно остаются запущенными до успешной замены. Проверяйте вывод команды и логи.
Это обновление выполняется на компьютере с приложением: изменения в GitHub сами
по себе не обновляют контейнеры на ноутбуке.
