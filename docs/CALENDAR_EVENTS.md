# События календаря: API

Первый этап: серверное хранение отдельных событий. Интерфейс создания событий
и отображение их в сетке месяца/недели ещё предстоит подключить.

Маршруты: GET/POST `/api/events`, GET/PUT/DELETE `/api/events/{id}`.
PUT заменяет все поля события. Неизвестный id возвращает 404; неверные данные — 422.
Поля: title (1–255 символов после удаления пробелов по краям), starts_at, ends_at,
location (до 255 символов, необязательно). Окончание строго позже начала.
Даты требуют явного смещения часового пояса. Хранение и ответы — UTC.

```json
{
  "title": "Консультация",
  "starts_at": "2026-12-01T10:00:00+03:00",
  "ends_at": "2026-12-01T11:00:00+03:00",
  "location": "Аудитория 210"
}
```

Добавляется новая таблица calendar_events при обычном старте API. Существующие
таблицы и записи не удаляются. Пока авторизации нет: события общие, как остальные
данные прототипа. Не использовать для личных данных в публичном интернете.

Проверки SQLite: жизненный цикл, UTC, события через полночь, порядок выдачи,
неизвестный id, неправильные даты и сохранность данных после отказа.
PostgreSQL и привязка пользователей требуют дальнейших интеграционных проверок.
