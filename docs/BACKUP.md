# Резервная копия PostgreSQL

Для работающего Compose из корня проекта: `bash scripts/backup.sh`.
Скрипт выводит путь нового custom-format pg_dump в backups/. Можно передать другую
папку первым аргументом. Нужен Docker и запущенный db; pg_dump берётся из того же
контейнера PostgreSQL. Хостовая установка PostgreSQL не требуется.

Файл создаётся с правами0600 и новым случайным именем, старые копии не перезаписываются.
Неудачная частичная копия удаляется. Скрипт проверяет, что архив читается pg_restore.
Копия содержит всю БД, включая хеши паролей и сессии: не публикуй её в GitHub/чат,
храни отдельно от ноутбука с ограниченным доступом. backups/ исключена из Git.

В одноразовом тестовом окружении: `STUDYBLOOM_TEST_RESTORE=1 python scripts/verify-restore.py`.
Проверка создаёт новую БД со случайным именем studybloom_restore_…, восстанавливает
дамп с остановкой при ошибке, сравнивает число строк всех таблиц и проверяет новую
задачу после восстановления (последовательность id). Затем удаляет только собственную
временную БД и тестовый файл. Основная БД не перезаписывается. Это выполняется в CI.

Не запускай тестовую проверку на используемом экземпляре: параллельные изменения
могут сделать сравнение количества строк неверным. Для реального восстановления
сначала подготовь отдельную БД/экземпляр, восстанови и проверь его, и только после
этого отдельно планируй переключение. Команды автоматической перезаписи рабочей БД
здесь намеренно нет. Личный JSON-архив не заменяет эту резервную копию.

Подтверждение в Ubuntu CI не означает установленную Linux VM в UTM на MacBook.
После установки гостя нужно отдельно проверить запуск, копию, сеть и доступ преподавателя.
